The mental model first

Think of your React app as one page that never reloads. React Router's job is to watch the browser's URL bar and decide which component to show based on what's currently typed there — like a receptionist checking a visitor's badge and pointing them to the right room, without the whole building needing to be rebuilt.

01

Install & the 3 core pieces

Every router setup rests on exactly three building blocks:

<BrowserRouter>

The outer wrapper. It turns on routing for everything inside it. Wrap your whole app once, at the top.

<Routes>

A container that looks at the current URL and picks one matching child route to render.

<Route>

A single rule: "if the URL matches path, render this element."

terminal 
npm install react-router-dom
src/main.jsx 
import { BrowserRouter } from "react-router-dom";
import App from "./App";

ReactDOM.createRoot(document.getElementById("root")).render(
  <BrowserRouter>
    <App />
  </BrowserRouter>
);
src/App.jsx 
import { Routes, Route } from "react-router-dom";
import Home from "./pages/Home";
import About from "./pages/About";

function App() {
  return (
    <Routes>
      <Route path="/" element={<Home />} />
      <Route path="/about" element={<About />} />
    </Routes>
  );
}

export default App;
💡
Rule of thumb: path is always a string in quotes. element is always JSX inside curly braces, because you're handing over an actual React element, not text.

03

Navigating with <Link> and <NavLink>

Never use a plain <a href=""> for internal navigation — it reloads the whole page. <Link> swaps the view instantly instead.

src/components/Navbar.jsx 
import { Link, NavLink } from "react-router-dom";

function Navbar() {
  return (
    <nav>
      <Link to="/">Home</Link>

      {/* NavLink knows when it's "active" */}
      <NavLink
        to="/about"
        className={({isActive}) => isActive ? "link active" : "link"}
      >
        About
      </NavLink>
    </nav>
  );
}
💡
to is the Link's version of href. className={'{ }'} takes a function here because NavLink hands you back isActive — that's why you see nested parentheses and braces.
04

Dynamic Route Params — useParams()

A colon :id inside a path string means "match anything here and remember it." Read that value back out with the useParams hook.

src/App.jsx 
<Route path="/users/:userId" element={<UserProfile />} />
src/pages/UserProfile.jsx 
import { useParams } from "react-router-dom";

function UserProfile() {
  const { userId } = useParams(); // { } because it destructures an object

  return {<h1>Viewing user: {userId}</h1>};
}

Visiting /users/42 renders "Viewing user: 42". No quotes around :userId when reading it — it's a live variable, not text.

05

Nested Routes & <Outlet />

Real apps share layout — a navbar/sidebar that stays while inner content changes. Nest <Route> tags, and use <Outlet /> inside the parent as a placeholder for whichever child matched.

src/App.jsx 
<Routes>
  <Route path="/dashboard" element={<DashboardLayout />}>
    <Route path="stats" element={<Stats />} />
    <Route path="settings" element={<Settings />} />
  </Route>
</Routes>
src/layouts/DashboardLayout.jsx 
import { Outlet } from "react-router-dom";

function DashboardLayout() {
  return (
    <div>
      <Sidebar />
      <Outlet />  {/* Stats or Settings renders here */}
    </div>
  );
}
💡
Notice the child paths "stats" have no leading slash. React Router appends them onto the parent, so the real URL is /dashboard/stats.
06

Index Routes — the default child

What should show at exactly /dashboard, with no child path? Use index — a boolean flag, not a string, so it never takes quotes.

src/App.jsx 
<Route path="/dashboard" element={<DashboardLayout />}>
  <Route index element={<Overview />} />  {/* no path, no quotes needed */}
  <Route path="stats" element={<Stats />} />
</Route>
07

Going somewhere in code — useNavigate()

Sometimes navigation must happen after logic runs — a form submit, a login check. Call the hook to get a function, then call that function.

src/pages/LoginForm.jsx 
import { useNavigate } from "react-router-dom";

function LoginForm() {
  const navigate = useNavigate(); // no braces — it's one function, not an object

  function handleSubmit() {
    login().then(() => {
      navigate("/dashboard");       // string path in ( )
      // navigate(-1) would go back one page in history
    });
  }

  return {<button onClick={handleSubmit}>Log in</button>};
}
💡
navigate(path) uses parentheses because it's a function call — always the pattern () right after a function name.
08

Reading the URL's query string — useSearchParams()

For /products?category=shoes&sort=price, the part after ? is a query string. This hook returns an array (hence square-bracket destructuring) — a reader and a setter, just like useState.

src/pages/Products.jsx 
import { useSearchParams } from "react-router-dom";

function Products() {
  const [searchParams, setSearchParams] = useSearchParams();

  const category = searchParams.get("category"); // "shoes"

  function sortByPrice() {
    setSearchParams({ category, sort: "price" });
  }

  return {<p>Category: {category}</p>};
}
09

useLocation() — knowing where you are

Returns an object describing the current URL in full detail. Useful for analytics, scroll-resets, or reading state passed silently between pages.

src/hooks/example.jsx 
import { useLocation } from "react-router-dom";

function PageTracker() {
  const location = useLocation();

  // location.pathname  → "/dashboard/stats"
  // location.search    → "?sort=price"
  // location.state     → any data sent via <Link state={{...}}>

  return null;
}
10

The catch-all 404 page

A single "*" matches anything nothing else caught. Put it last in the list — order matters, React Router picks the first match.

src/App.jsx 
<Routes>
  <Route path="/" element={<Home />} />
  <Route path="/about" element={<About />} />
  <Route path="*" element={<NotFound />} />
</Routes>
11

Protected routes — gatekeeping a page

Wrap a route's element in a small guard component. It checks a condition, then either shows the page or redirects with <Navigate />.

src/components/ProtectedRoute.jsx 
import { Navigate } from "react-router-dom";

function ProtectedRoute({ children }) {
  const isLoggedIn = useAuth(); // your own logic

  if (!isLoggedIn) {
    return {<Navigate to="/login" replace />};
  }

  return children;
}
src/App.jsx 
<Route
  path="/dashboard"
  element={
    <ProtectedRoute>
      <Dashboard />
    </ProtectedRoute>
  }
/>
12

The modern way — Data Routers (v6.4+ / v7)

Current React Router (v7, the actively maintained line in 2026) favors createBrowserRouter over writing <Routes> by hand. Routes become a plain JS array of objects, and each route can fetch its own data via a loader before it even renders.

src/main.jsx 
import { createBrowserRouter, RouterProvider } from "react-router-dom";

const router = createBrowserRouter([
  {
    path: "/",
    element: {<Root />},
    children: [
      { index: true, element: {<Home />} },
      {
        path: "users/:id",
        element: {<UserProfile />},
        loader: ({ params }) => fetchUser(params.id),
      },
    ],
  },
]);

ReactDOM.createRoot(document.getElementById("root")).render(
  {<RouterProvider router={router} />}
);
💡
Note the shift in brackets: routes are now a JS array of objects [ { }, { } ], not JSX tags. Keys like path: and element: use a colon, not =, because this is plain JavaScript object syntax, not JSX props.
⚠️
Naming note: Newer React Router releases (v7+) consolidated the package as react-router, with react-router-dom kept only for backward compatibility with existing v6 imports. If you start a brand-new project today, check the current docs at reactrouter.com for which package name is recommended — the syntax above works either way.
